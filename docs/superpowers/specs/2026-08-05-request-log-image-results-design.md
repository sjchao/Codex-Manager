# 请求日志生图结果设计

## 目标

在请求日志的生图模型页直接显示成功请求的图片缩略图。点击缩略图可查看原图。图片结果必须同时支持 Linux Service Web UI 和 Tauri 桌面端；清空请求日志时，关联图片文件必须一并删除。

## 已确认的产品决策

- 生图日志采用表格内直接显示缩略图的布局。
- 图片写入运行数据目录下自动创建的子目录。
- Linux Service Web UI 和 Tauri 桌面端都必须支持预览。
- 不提供公开的静态图片路径，也不依赖上游图片 URL 的有效期。
- 历史日志不回填图片；没有可读结果的日志显示 `-`。

## 存储设计

服务从 `CODEXMANAGER_DB_PATH` 取得数据库文件路径，并将图片根目录解析为其父目录下的 `request-log-images/`。例如数据库为 `./data/codexmanager.db` 时，图片写入 `./data/request-log-images/`。首次保存时调用 `create_dir_all` 自动建目录。

每个成功的图片请求使用独立的子目录和随机文件名保存图片。数据库迁移为 `request_logs` 增加 `image_results_json` 字段，保存有序的受控文件名、MIME 类型和字节数；不保存绝对路径，也不保存上游 URL。请求日志列表将该字段映射为 `imageResults` 元数据。

每张图片最大允许 20 MiB，每个请求最多缓存 64 MiB。超过限制、MIME 类型不是图片、上游下载失败或本地写入失败时，不影响原始 API 响应和请求成功状态，只记录告警并让该条日志没有相应预览。

## 响应归档

仅对最终状态为 2xx 且 `model_type = image` 的非流式响应归档图片。HTTP bridge 已经在此路径缓冲响应；缓存层会先在大小上限内解压 zstd 响应，再解析该缓冲副本，不改变传给调用方的响应内容。

支持 OpenAI 图片响应的两种常见结果：

- `data[].b64_json`：解码后直接写入图片目录。
- `data[].url`：只接受 `http` 和 `https` URL，在调用方收到上游响应后以 10 秒超时下载并写入图片目录。
- 供应商直接返回的 PNG、JPEG、GIF、WebP 原始图片，以及 zstd 压缩后的上述图片。

缓存失败只是日志附属功能失败，不能使生图 API 请求变成失败。若数据库日志写入失败，刚写入但尚未被记录引用的图片必须尽力删除。

## 读取与展示

新增 `requestlog/images/read` RPC。它只接受日志 trace ID，数据库按该日志的 `image_results_json` 读取受控文件名，校验解析后的路径仍位于 `request-log-images/` 内，再以数据 URL 返回图片内容。不会接收或返回任意文件系统路径。

Tauri 为该 RPC 增加对应 command，前端通过既有 `invoke` 和 `withAddr()` 读取。Web 端为同一 command 增加 `/api/rpc` 映射，继续受现有 Web 会话鉴权保护。两端不新增未经鉴权的文件服务路由。

日志列表只返回小型图片元数据。`ImageResultCell` 在生图 Tab 中为当前页有结果的日志按需查询图片数据，并以固定尺寸、`object-fit: cover` 的缩略图显示。点击缩略图使用对话框展示同一份原图数据。请求列表的其他 Tab 不读取图片数据。

## 清空语义

`requestlog/clear` 在删除 `request_logs` 前读取全部图片资产引用，并且只删除受控图片根目录中的目标文件。不存在的文件视为已清理；路径非法、目录外路径或其他删除错误会使操作失败并保留数据库日志，便于用户修正权限后重试。文件删除成功后才调用现有的请求日志删除逻辑。

前端仅在清空 RPC 成功时失效请求日志、汇总和图片预览查询，并移除对应图片查询缓存。现有 `request_token_stats` 保留规则不变。

## 兼容性和安全性

- 新字段对历史日志默认为空数组，不影响现有查询、筛选或统计。
- 图片目录从实际数据库路径推导，兼容 `./data/codexmanager.db`、绝对 Linux 数据目录和 Tauri 默认应用数据目录。
- 上游 URL 的下载不携带账号密钥、Cookie 或调用方请求头。
- API 返回的图片数据仅经过既有 RPC 通道传递，Web 端仍受认证 Cookie 保护。

## 验证范围

- Core storage 测试：图片元数据写入、读取及迁移兼容。
- Service 测试：`b64_json` 和本地 HTTP URL 的结果归档、自动建目录、缓存失败不改变 2xx 响应、RPC 只按 trace ID 返回受控文件。
- 清空测试：文件与请求日志同时删除；无法删除时保留日志；token 统计仍可汇总。
- 前端测试和构建：图片 Tab 的缩略图和空态、清空后的查询缓存失效，以及 `pnpm run build:desktop`。
